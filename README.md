صفحة هبوط بصفحة واحدة، هدفها الوحيد أن يترك الوالد رقمه لتتصلوا به.
مبنيّة بـ Next.js وTailwind، والبيانات تُحفَظ في Supabase.

الفكرة المحورية: **الصفحة لا تشرح كل شيء، بل تفتح المكالمة التي يُشرح فيها كل شيء.**

## 2. تبديل النصوص

**كل نصوص الصفحة في ملف واحد: `content/site.ts`**

لا تحتاج فتح أي ملف آخر لتغيير كلمة. الملف مقسّم إلى أقسام واضحة:

| المتغيّر | ماذا يتحكّم فيه |
|---|---|
| `contact` | الهاتف، واتساب، البريد، الروابط، الموقع، التوقيت |
| `cta` | نصوص الأزرار (اطلب مكالمة…) |
| `hero` | العنوان الأول والسطر الداعم والبطاقات الثلاث |
| `pain` | قسم الألم — المشهد الذي يعرفه الولي |
| `change` | قسم التحوّل — ما الذي يتغيّر في الطفل |
| `activities` | الأنشطة وصورها ونصوصها |
| `trust` | قسم الطمأنينة — ما يطمئن الولي |
| `faq` | الأسئلة الشائعة الستّة |
| `form` | عناوين الاستمارة وتسميات الحقول ورسائل النجاح والخطأ |
| `footer` / `nav` | التذييل وشريط التنقّل |

مثال — تغيير عنوان الصفحة الرئيسي:

```ts
export const hero = {
  title: 'العنوان الجديد هنا',
  ...
};
```

احفظ الملف، ثم `git commit` و`git push` — وVercel ينشر التحديث تلقائياً.

## 2.1 بنية القمع التسويقي

الترتيب مقصود، ولا يُغيَّر بلا سبب:

| # | القسم | وظيفته في القمع |
|---|---|---|
| 1 | Hero | الوعد + أول CTA |
| 2 | الألم | يعترف بالمشهد الذي يعيشه الولي (الشاشة، الطاقة، الخجل، الوحدة) |
| 3 | التحوّل | ما الذي يتغيّر في الطفل — الفائدة لا الخاصية |
| 4 | الأنشطة | البرهان البصري: صور حقيقية لما يفعله فعلاً |
| 5 | الطمأنينة | يزيل خوف الولي نفسه (التأقلم، النظام، التواصل، النقل) |
| 6 | أسئلة | يزيل الاعتراضات الأخيرة |
| 7 | الاستمارة | التحويل |

**تحت كل قسم من 2 إلى 5 يوجد زوج CTA** (اطلب مكالمة + واتساب) مع سطر
تحفيزي مختلف في كل مرّة — مصدره `ctaNote` في كل قسم.

**قاعدة عدم التكرار:** الأعمار والتوقيت والنقل تُذكر في بطاقات الـHero
وفي الأسئلة الشائعة فقط. لا تكرّرها في أقسام أخرى ولا في التذييل.

## 3. إضافة أو تبديل الصور

الصور في `public/images/`:

| الملف | أين يظهر |
|---|---|
| `logo.png` | الشريط العلوي والتذييل (بخلفية شفّافة) |
| `hero-drawing.webp` | صورة الـHero التي تملأ الشاشة |
| `horse.webp` | نشاط ركوب الخيل (بطاقة عريضة) |
| `pool.webp` | نشاط السباحة (بطاقة عريضة) |
| `craft.webp` | الأنشطة اليدوية |
| `discover.webp` | نشاط الاكتشاف |
| `classroom.webp` | التعلّم داخل القاعة |

### لإضافة صورة جديدة إلى الشبكة

1. ضَع الصورة في `public/images/` — يُفضَّل صيغة `.webp` وعرض 1400 بكسل.
2. أضِف سطراً في `content/site.ts` داخل `activities.items`:

```ts
{
  src: '/images/nom-de-limage.webp',
  alt: 'وصف الصورة للمكفوفين',
  title: 'اسم النشاط',
  body: 'جملة تشرح ماذا يكسب الطفل من هذا النشاط.',
  pos: 'object-[50%_35%]', // اختياري: موضع القصّ إن كان الوجه يُقطَع
  span: 'wide',            // اختياري: بطاقة عريضة بدل صغيرة
},
```

**قاعدة الشبكة:** بطاقتان `wide` في الصف الأول، وثلاث بطاقات عادية بعدهما.
حافظ على هذا التوازن (2 عريضة + 3 عادية، أو 3 عادية فقط) حتى لا يتشوّه الصف.

### لتحويل صورة إلى WebP

```bash
npx sharp-cli --input photo.jpg --output public/images/photo.webp resize 1400 --format webp
```

> **ملاحظة عن اللوقو:** الملف الأصلي كان صورة مربّعة بخلفية رمادية وشريط أسود
> من لقطة فيديو. أُزيلت الخلفية فقط وقُصَّت الحواف الفارغة — بلا أي تعديل على
> الألوان أو الأشكال. النتيجة PNG بخلفية شفّافة.

## 4. ربط Supabase

المشروع منشأ باسم **mama-zayneb**.

### المتغيّرات المطلوبة

في Vercel → **Settings → Environment Variables**، أضِف:

| المتغيّر | القيمة | أين تجدها |
|---|---|---|
| `SUPABASE_URL` | رابط المشروع | Supabase → Project Settings → **Data API** → Project URL |
| `SUPABASE_SERVICE_ROLE_KEY` | المفتاح السرّي | Supabase → Project Settings → **API Keys** → `service_role` |

**المتغيّران اختياريان.** المشروع يعمل بدونهما: الرابط والمفتاح العام
(anon) مكتوبان في `lib/supabase/config.ts`، والإدراج يمرّ عبر سياسة
`leads_public_insert`. إضافة `service_role` ترفع مستوى الأمان لأن
الإدراج يتجاوز RLS، لكنّها ليست شرطاً للتشغيل.

> ⚠️ مفتاح `service_role` سرّي تماماً. لا تضعه في متغيّر يبدأ بـ `NEXT_PUBLIC_`،
> ولا في أي ملف يُرفَع إلى GitHub. من يملكه يملك قاعدة البيانات كاملة.

### كيف يعمل الإدراج

المتصفّح **لا يتصل بـSupabase إطلاقاً**. الاستمارة ترسل إلى `/api/lead`
(مسار في الخادم)، وهو من يدرج الصف باستعمال `service_role`.
هذا يمنع أي عبث من المتصفّح.

### كيف أرى المسجّلين من Table Editor

1. افتح [supabase.com/dashboard](https://supabase.com/dashboard) وسجّل الدخول.
2. اختر مشروع **mama-zayneb**.
3. من القائمة الجانبية اليسرى اضغط **Table Editor** (أيقونة الجدول).
4. من قائمة الجداول في الأعلى اختر **`leads`** ضمن schema `public`.
5. ستظهر كل الطلبات. الأعمدة:

   | العمود | المعنى |
   |---|---|
   | `created_at` | وقت وصول الطلب |
   | `parent_name` | اسم الولي |
   | `phone` | رقم الهاتف (بصيغة موحّدة `07XXXXXXXX`) |
   | `child_age` | عمر الطفل الذي اختاره |
   | `desired_start` | متى يودّ البدء |
   | `note` | ملاحظته إن كتب واحدة |
   | `utm_source` / `utm_campaign` | من أي إعلان جاء |
   | `status` | حالة المتابعة، تبدأ بـ `new` |

6. **لترتيب الأحدث أولاً:** اضغط **Sort** في الشريط العلوي → اختر
   `created_at` → **descending**.
7. **لتغيير حالة المتابعة:** اضغط مرّتين على خانة `status` في الصف واختر
   إحدى القيم: `new` · `contacted` · `visited` · `enrolled` · `lost`.
8. **لتصدير كل الطلبات إلى Excel:** اضغط زر **⋯** أعلى الجدول →
   **Download as CSV**.

### الأمان (RLS)

الحماية على مستوى الصف مفعّلة على جدول `leads`:

- **الإدراج**: مسموح لـ`anon` و`authenticated`.
- **القراءة**: للمصادَقين فقط — لا يستطيع أي زائر قراءة أرقام الهواتف.
- **التعديل**: للمصادَقين فقط.
- **الحذف**: ممنوع تماماً (لا توجد سياسة حذف).

ملفّ الـmigration في `supabase/migrations/`.

## 5. إعداد الإشعار الفوري (Database Webhook)

يرسل نسخة من كل طلب جديد فور وصوله إلى رابط تختاره (تلغرام عبر n8n، أو أي وسيط).

### الخطوات في لوحة Supabase

1. افتح مشروع **mama-zayneb** في [supabase.com/dashboard](https://supabase.com/dashboard).
2. من القائمة الجانبية: **Integrations** → **Database Webhooks**
   (أو **Database** → **Webhooks** حسب نسخة اللوحة).
3. إن ظهر زرّ **Enable webhooks** اضغطه أولاً — يفعّل إضافة `pg_net`.
4. اضغط **Create a new hook**.
5. املأ الحقول:

   | الحقل | القيمة |
   |---|---|
   | **Name** | `new_lead_notification` |
   | **Table** | `leads` (schema: `public`) |
   | **Events** | ✅ **Insert** فقط (اترك Update وDelete فارغين) |
   | **Type of webhook** | **HTTP Request** |
   | **Method** | **POST** |
   | **URL** | الصق هنا رابط الـWebhook الخاص بك من n8n |
   | **Timeout** | `5000` ms |

6. في **HTTP Headers** أضِف:
   - `Content-Type` → `application/json`
   - (اختياري ولكن مُستحسَن) `x-webhook-secret` → كلمة سرّ تخترعها،
     وتتحقّق منها في n8n لترفض أي طلب لا يحملها.

7. اضغط **Create webhook**.

### ما الذي يصل إلى الرابط

يصل JSON بهذا الشكل عند كل تسجيل جديد:

```json
{
  "type": "INSERT",
  "table": "leads",
  "schema": "public",
  "record": {
    "id": "…",
    "created_at": "2026-09-05T15:32:11.204Z",
    "parent_name": "أمينة بن علي",
    "phone": "0771888841",
    "child_age": "من سنتين إلى 3 سنوات",
    "desired_start": "في أقرب وقت",
    "note": null,
    "utm_source": "facebook",
    "utm_campaign": "rentree_2026",
    "status": "new"
  },
  "old_record": null
}
```

في n8n: أنشئ **Webhook node** (POST)، انسخ رابطه إلى الحقل أعلاه،
ثم أضِف **Telegram node** برسالة مثل:

```
🔔 تسجيل جديد
الاسم: {{ $json.record.parent_name }}
الهاتف: {{ $json.record.phone }}
عمر الطفل: {{ $json.record.child_age }}
البدء: {{ $json.record.desired_start }}
ملاحظة: {{ $json.record.note }}
```

### للاختبار

املأ الاستمارة على الموقع برقم حقيقي، ثم راقب n8n.
إن لم يصل شيء: Supabase → **Logs** → **Postgres Logs** وابحث عن `net.http_post`.

## 6. وضع بيكسل ميتا

### المعرّف المستعمل

البيكسل **مربوط وجاهز**. المعرّف `2615027122286387` مكتوب مباشرة في
`lib/pixel.ts` و`app/layout.tsx`، فلا تحتاج ضبط أي شيء في Vercel.

معرّفات البيكسل ليست سرّية — تظهر في مصدر الصفحة لأي زائر، ولهذا
لا مانع من كتابتها في الكود.

**لتغيير البيكسل لاحقاً،** لك طريقان:

- **الأسهل:** عدّل `FALLBACK_PIXEL_ID` في `lib/pixel.ts` والقيمة في
  `app/layout.tsx`، ثم `git push`.
- **بلا لمس الكود:** أضِف `NEXT_PUBLIC_META_PIXEL_ID` في
  Vercel → Settings → Environment Variables، ثم **Redeploy**.
  قيمته تتقدّم على المكتوب في الكود.

### طريقة التركيب — ولماذا تختلف عمّا يعطيك ميتا

لوحة ميتا تطلب لصق سكربت جاهز بين `<head>` و`</head>`. **لا تفعل ذلك هنا.**
السكربت مُدمَج في المشروع بنسخة أفضل:

| ما تعطيه ميتا | ما هو مطبَّق عندنا |
|---|---|
| يحمّل السكربت فور فتح الصفحة | يحمّله بعد **أول تفاعل** من الزائر — Lighthouse يبقى فوق 90 |
| `PageView` فقط | `PageView` + `ViewContent` + `Lead` |
| — | `<noscript>` مركّب أيضاً لزوّار بلا جافاسكربت |

لو لصقت سكربت ميتا يدوياً في `<head>` لأصبح لديك بيكسلان يطلقان
`PageView` مرّتين — وستفسد أرقام حملتك.

### الأحداث المرسَلة

| الحدث | متى يُطلَق |
|---|---|
| `PageView` | بعد **أول تفاعل** من الزائر (تمرير، لمس، أو نقرة) — لا قبل ذلك، حفاظاً على سرعة الصفحة |
| `ViewContent` | عند وصول الزائر إلى قسم الاستمارة (35% منه ظاهر) |
| `Lead` | عند **نجاح الإرسال فقط** — لا عند الضغط على الزر |

### Conversions API

البنية جاهزة في `app/api/capi/route.ts` لكنها **غير مفعّلة**؛ المسار يعيد `501`
حتى تُضاف `META_CAPI_ACCESS_TOKEN`. خطوات التفعيل مشروحة داخل الملف نفسه.

## 6.5 منصّة الإدارة (`/dashboard`)

واجهة مستقلّة داخل نفس المشروع لرؤية التسجيلات ومتابعتها.

### الدخول — برقم الهاتف

| الرابط | `https://mama-zayneb.vercel.app/login` |
|---|---|

**كيف يعمل الدخول بالرقم بلا مزوّد SMS:** رقم الهاتف يُحوَّل داخلياً إلى
هوية بالشكل `<الرقم>@staff.mamazayneb.dz`. هذا النطاق وهميّ ولا يُرسَل
إليه بريد إطلاقاً — هو مجرّد شكل تتطلّبه خدمة المصادقة. النتيجة: لا اشتراك
في خدمة رسائل، ولا كشف لبريد أي موظّف. المنطق في `lib/staffAuth.ts`.

الأرقام المسجّلة حالياً:

| الرقم | الدور |
|---|---|
| `0771888841` | المالِكة |
| `0770000001` | المشرف التقني (رقم مؤقّت) |

**غيّر كلمتَي المرور بعد أول دخول** من Supabase → Authentication → Users
→ ⋯ → Reset password.

### من يستطيع الدخول

لا يكفي أن يكون للشخص حساب في Supabase — يجب أن يكون **مسجّلاً في جدول
`public.staff`**. هذا يمنع أي شخص ينشئ حساباً بنفسه من رؤية أرقام هواتف
الأولياء.

لإضافة موظّف جديد:

1. Supabase → **Authentication** → **Users** → **Add user**
   (فعّل *Auto Confirm User*). في خانة البريد اكتب هوية الدخول
   بالشكل: `0669112233@staff.mamazayneb.dz` — أي رقم هاتفه ثم النطاق.
2. انسخ الـ`User UID` الظاهر في القائمة.
3. Supabase → **SQL Editor** ونفّذ:

```sql
insert into public.staff (user_id, full_name, role, phone, email)
values ('الصق-الـUID-هنا', 'اسم الموظّف', 'admin', '0669112233', 'بريده@مثال.com');
```

عمود `phone` هو ما يُعرَض في المنصّة، و`email` للتواصل فقط لا للدخول.

الأدوار المتاحة: `owner` · `admin` · `viewer` (الدور محفوظ للتوسّع لاحقاً؛
حالياً الثلاثة يرون نفس الشيء).

لسحب الصلاحية: `delete from public.staff where user_id = '...';`

### لفتح وحدة جديدة لاحقاً

1. غيّر `status` إلى `'live'` في `content/dashboard.ts`.
2. أنشئ `app/dashboard/<slug>/page.tsx` بمحتواها الحقيقي.
3. أضِف جداولها في migration جديدة مع سياسة `using (public.is_staff())`.
4. لأيقونة جديدة: أضِف اسمها في `content/dashboard.ts` وسجّلها في

البنية مهيّأة لذلك: الشريط الجانبي والصلاحيات وقالب الصفحة المقفلة تعمل
جميعها انطلاقاً من `content/dashboard.ts`.

## 6.6 الإشعارات الفورية

هدفها واحد: أن تتصل المالِكة بالولي **وهو ما يزال مهتمّاً**. الولي الذي
يترك رقمه الآن يكون في ذروة اهتمامه، وهذا الاهتمام يبرد خلال ساعات.

### طبقتان تعملان معاً

| الطبقة | متى تعمل | تحتاج إعداداً؟ |
|---|---|---|
| **التحديث اللحظي** (Supabase Realtime) | والمنصّة مفتوحة | لا — تعمل الآن |
| **الإشعار الفوري** (Web Push) | حتى والمنصّة مغلقة والهاتف في الجيب | نعم — متغيّران |

التحديث اللحظي يجعل التسجيل الجديد يظهر في القائمة بلا إعادة تحميل،
ويطلق إشعاراً داخل النظام إن كان الإذن ممنوحاً. يعمل في الخلفية بلا أي
شارة مرئية.

> **عطل صُلِح:** كانت قناة الاشتراك تُفتَح أحياناً قبل أن يجهّز عميل
> Supabase جلسة المستخدم من الكوكيز (سباق توقيت عند أول تحميل)، فتُفتَح
> القناة بصفة «مجهول» ترفضها سياسة `is_staff()` ولا يصل أي حدث — دون أي
> خطأ ظاهر. الإصلاح في `components/dashboard/LiveLeads.tsx`: ننتظر
> `getSession()` صراحةً قبل الاشتراك.

### تشغيل الإشعار الفوري — خطوتان

في Vercel → **Settings → Environment Variables** أضِف:

| المتغيّر | القيمة |
|---|---|
| `VAPID_PRIVATE_KEY` | المفتاح الخاص المولَّد للمشروع (اطلبه من المطوّر) |
| `SUPABASE_SERVICE_ROLE_KEY` | من Supabase → Project Settings → API Keys |

ثم **Redeploy**. المفتاح الثاني ضروري لأن قراءة اشتراكات الأجهزة تتجاوز
سياسات RLS.

> **مهم:** بدون هذين المتغيّرين لا يتعطّل شيء. التسجيلات تُحفَظ كالمعتاد،
> والتحديث اللحظي يعمل، وتُتخطّى الإشعارات بصمت فقط.

### كيف تفعّلها المالِكة

1. تفتح `/dashboard` من هاتفها.
2. تضغط **«فعّلي الإشعارات»** في البطاقة الوردية أعلى الصفحة.
3. يسألها المتصفّح فتوافق.

بعدها يصلها تنبيه لحظة وصول أي طلب، مع اسم الولي، وبالضغط عليه تفتح
المنصّة على التسجيل مباشرة.

> **عطل صُلِح — «يعمل على الهاتف ولا يعمل على الحاسوب»:** البطاقة كانت
> تثق بـ`Notification.permission === 'granted'` وحده كدليل على أن
> الإشعارات تعمل، بينما هذا لا يعني أن الاشتراك حُفظ فعلاً على الخادم —
> قد يكون فشل حفظه بصمت في محاولة سابقة (فشل شبكة، أو مفتاح VAPID تغيّر
> بين بيئتَي تطوير ونشر). النتيجة: جهاز يظهر عليه «الإذن ممنوح» لكن لا
> يصله شيء أبداً. الإصلاح في `lib/push/client.ts`:
> - `hasActiveSubscription()` تتحقّق من الاشتراك الفعلي في عامل الخدمة،
>   لا من الإذن وحده.
> - `enablePush()` تقارن مفتاح أي اشتراك سابق بالمفتاح الحالي، وتُلغي
>   القديم وتُعيد الاشتراك عند أي اختلاف.
> - البطاقة لا تختفي بنجاح وهمي؛ تختفي فقط بعد تأكيد الحفظ على الخادم.

### تثبيت المنصّة على آيفون — دعوة تلقائية لمرّة واحدة

Safari يرفض تفعيل الإشعارات الفورية لأي موقع لم يُضَف إلى الشاشة
الرئيسية. لهذا تظهر تلقائياً عند أول فتح للمنصّة من آيفون (Safari) بطاقة
أسفل الشاشة:

- تشرح **لماذا** بلغة الفائدة لا التقنية: «إشعارات فورية حتى والمنصّة
  مغلقة، وتُفتَح من أيقونة كأي تطبيق — بلا متصفّح ولا رابط تبحثين عنه.»
- ثلاث خطوات مرقّمة بأيقوناتها: زرّ المشاركة ← «إضافة إلى الشاشة
  الرئيسية» ← «إضافة».
- **تظهر مرّة واحدة فقط**: تُغلَق نهائياً بعد الضغط على «ليس الآن» أو أي
  زرّ إغلاق (تُحفَظ في `localStorage`)، ولا تظهر إطلاقاً إن كانت المنصّة
  مفتوحة أصلاً بصفة مثبَّتة (`display-mode: standalone`).
- لا تظهر على أندرويد أو الحاسوب — إذن الإشعارات هناك يُطلَب مباشرة من
  البطاقة الوردية بلا حاجة للتثبيت.

المنطق في `components/dashboard/IosInstallPrompt.tsx`، والنصوص في
`iosInstall` بـ`content/dashboard.ts`.

### الملفات

```
public/sw.js                       عامل الخدمة الذي يعرض الإشعار
public/manifest.webmanifest        يجعل المنصّة قابلة للتثبيت كتطبيق
lib/push/config.ts                 المفتاح العام
lib/push/client.ts                 طلب الإذن، حفظ الاشتراك، والتحقّق من صحّته
lib/push/send.ts                   إرسال الإشعار من الخادم
app/api/push/subscribe/route.ts    حفظ اشتراك الجهاز
components/dashboard/PushCard      بطاقة طلب الإذن (تختفي بعد التفعيل المؤكَّد)
components/dashboard/LiveLeads     الاشتراك في البثّ اللحظي (بلا واجهة)
components/dashboard/IosInstallPrompt  دعوة التثبيت على آيفون
```

لتعديل نصّ الإقناع أو نصّ الإشعار: `push` و`iosInstall` في
`content/dashboard.ts`.

### استجابة الأزرار في اللوحة

كل زرّ ورابط في `/dashboard` يحمل صنف `.tap-feedback` (معرَّف في
`app/globals.css`): يصغر العنصر فوراً لحظة الضغط بـCSS خالص — لا ينتظر
أي استجابة شبكة — فتشعرين بالضغطة فوراً حتى لو تأخّر تحميل الصفحة
التالية. ولكل قسم في اللوحة `loading.tsx` يعرض هيكلاً بصرياً فوراً عند
الانتقال إليه، بدل أن تبقى الشاشة فارغة أثناء انتظار البيانات.

## 8. ماذا ينتظر محتوى منك

| # | ما هو ينقص | أين يوضَع |
|---|---|---|
| 1 | **صور إضافية لأنشطة أخرى** إن وُجدت | `public/images/` + `gallery.items` في `content/site.ts` |
| 2 | **العنوان الدقيق للروضة** — حالياً «تاسوست، جيجل» فقط | `contact.city` |
| 3 | **أيام العمل** — التوقيت معروف لكن الأيام لا | `contact.hours` + سؤال «ما أوقات العمل؟» في `faq` |
| 5 | **رابط الـWebhook من n8n** | Supabase → Database Webhooks |
| 6 | **صورة مشاركة (OG image)** للفيسبوك والواتساب | `app/opengraph-image.png` + `metadata.openGraph` |
| 7 | **شهادات الأولياء** إن أردت إضافة القسم لاحقاً | قسم جديد + `content/site.ts` |

لم أضِف أي شهادات أو أرقام لأنها غير مؤكّدة — أرسلها وأضيفها.
